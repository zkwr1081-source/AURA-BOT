# AURA Bot

بوت Telegram عربي بسيط بهيكل أقسام تفاعلية، مع إعداد آمن للرمز عبر متغير بيئة.

## المتطلبات

- Python 3.10+
- Telegram Bot Token جديد من BotFather

## التشغيل محلياً

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN="ضع_الرمز_محلياً"  # PowerShell: $env:TELEGRAM_BOT_TOKEN="..."
python main.py
```

لا تضع الرمز في `main.py` أو GitHub. انسخ `.env.example` كمرجع فقط؛ لا ترفع ملف `.env`.

## الوظائف الحالية

- `/start` يعرض لوحة الأقسام.
- أزرار الأقسام تعرض وصفاً تعريفياً.
- `/request` يتيح للعميل إرسال طلب عرض سعر بعد موافقته على حفظ بيانات Telegram والرسالة.
- تُحفظ الطلبات في SQLite محلياً، ويمكن إرسال إشعار إلى `ADMIN_CHAT_ID`.
- الدفع معطّل عمداً إلى أن تُربط بوابة دفع حقيقية وتُختبر؛ لا توجد روابط دفع وهمية.

### إعداد استقبال الطلبات

أضف `ADMIN_CHAT_ID` اختيارياً إلى متغيرات بيئة الخادم ليصلك إشعار بالطلبات الجديدة. يمكن تغيير مسار قاعدة البيانات عبر `LEADS_DB_PATH` (الافتراضي `aura_leads.sqlite3`). مدة الاحتفاظ الافتراضية بالسجلات 90 يوماً، ويمكن ضبطها عبر `LEADS_RETENTION_DAYS` ضمن المجال 1–3650؛ تُنظّف السجلات المنتهية عند بدء البوت، وعند حفظ طلب جديد، وبمهمة دورية كل 24 ساعة. يحدّ البوت الطلبات إلى 3 لكل مستخدم خلال 24 ساعة متحركة افتراضياً (قابل للضبط عبر `LEADS_MAX_PER_USER_24H` من 1 إلى 20) لمنع الإغراق. يمكن للمستخدم حذف سجلاته المحلية عبر `/forget`. النسخ التي سبق إرسالها إلى محادثة الإدارة لا يحذفها الأمر تلقائياً. راجع `PRIVACY.md`. لا تضع أسراراً في GitHub. اطلب من العملاء عدم إرسال كلمات المرور أو رموز التحقق أو بيانات الدفع.

## النشر

يمكن تشغيل البوت على خادم Python يدعم عملية طويلة الأمد. أضف `TELEGRAM_BOT_TOKEN` في مخزن أسرار مزود الاستضافة، ثم شغّل `python main.py`. هذا المستودع لا يحتوي حالياً على استضافة عامة أو رابط تجربة ويب؛ البوت يُجرّب عبر Telegram بعد تشغيله وربطه برمز صالح.

## الأمان

إذا سبق نشر رمز البوت داخل Git، ألغِه فوراً من BotFather باستخدام `/revoke` وأنشئ رمزاً جديداً. حذف الرمز من الملف الحالي لا يزيله من تاريخ Git السابق.
